# Epic 14: Agentic AI Features

**Date:** 2026-01-03
**Context Commit:** 5de85412d455d5d7e9cccdd4a2bebd518b28a6a5
**Related ADR:** [ADR: Agentic AI System Architecture](../adrs/agentic-system-adr.md)

## Overview

This epic introduces AI-powered features to enhance user interaction with economic data and news. The features leverage the `ecox-agents` component with Pydantic AI to provide intelligent summarization and natural language querying capabilities.

**Key Capabilities:**
1. **News Summarization** - Generate concise summaries of lengthy economic news articles
2. **Dataset Q&A** - Answer user questions by querying the appropriate datasets

---

## User Stories

### US-14.1: Summarize News Article

**As a** user viewing a news entry
**I want to** generate an AI summary of the article
**So that** I can quickly understand the key points without reading the full text

**Acceptance Criteria:**

- [ ] A "Summarize" button appears in the news entry modal when `content_full` is available
- [ ] Clicking the button triggers an async request to the agents service
- [ ] A loading indicator shows while the summary is being generated
- [ ] The summary is displayed below the original content (max 500 words)
- [ ] The summary includes:
  - Concise overview of the article (2-3 sentences)
  - Key economic indicators mentioned (if any)
  - Sentiment classification (positive/negative/neutral)
  - Key data points extracted (interest rates, growth figures, etc.)
- [ ] Error states are handled gracefully with user-friendly messages
- [ ] The summary can be regenerated by clicking the button again

**Technical Notes:**

- Uses `ecox-agents` summarizer agent (`agents/summarizer.py`)
- Input: `NewsEntry.content_full` from `/api/news/entries/{id}`
- Output: Structured `NewsSummary` response with summary, sentiment, key_indicators
- UI integration via htmx POST to `/api/agents/summarize/news/{entry_id}`

---

### US-14.2: View Cached News Summary

**As a** user returning to a previously summarized article
**I want to** see the cached summary immediately
**So that** I don't have to wait for regeneration

**Acceptance Criteria:**

- [ ] Once generated, summaries are cached in the database
- [ ] Cached summaries are returned instantly without calling the LLM
- [ ] The cache timestamp is displayed (e.g., "Summarized 2 hours ago")
- [ ] A "Regenerate" option allows users to request a fresh summary
- [ ] Summaries are invalidated if the article content is updated

**Technical Notes:**

- New `NewsSummary` model linked to `NewsEntry` via foreign key
- Fields: `summary_text`, `sentiment`, `key_indicators` (JSON), `extracted_data` (JSON), `created_at`, `model_version`
- Cache check before LLM call in summarizer agent

---

### US-14.3: Ask Questions About Economic Data

**As a** user
**I want to** ask natural language questions about economic data
**So that** I can quickly find information without knowing exact dataset codes or filters

**Acceptance Criteria:**

- [ ] A Q&A input box is available in the main UI (new tab or sidebar)
- [ ] Users can type questions like:
  - "What is the inflation rate in Germany this quarter?"
  - "Show me GDP growth for France in 2023"
  - "Compare unemployment rates in EU countries"
- [ ] The system:
  1. Interprets the question to identify relevant concepts (inflation, GDP, unemployment)
  2. Searches available datasets for matching indicators
  3. Applies appropriate filters (geo, time_period)
  4. Returns the data with clear attribution
- [ ] Results include:
  - The answer to the question
  - Source dataset and indicator used
  - Link to explore the full dataset
  - Confidence level (high/medium/low)
- [ ] If no data is found, helpful suggestions are provided
- [ ] Conversation history is maintained within the session

**Example Interactions:**

| User Question | Expected Response |
|---------------|-------------------|
| "What is the inflation in Germany this quarter?" | "The HICP inflation rate in Germany (DE) for 2025-Q4 is 2.3%. Source: Eurostat prc_hicp_mv12r" |
| "Show GDP for France" | "France (FR) GDP for 2024: 2,803,168 million EUR. Source: Eurostat nama_10_gdp. [View Dataset]" |
| "Unemployment in Spain vs Italy" | "Unemployment rates: Spain (ES): 11.2%, Italy (IT): 7.8% (2025-Q3). Source: Eurostat une_rt_q" |

**Technical Notes:**

- Uses `ecox-agents` Q&A agent (`agents/qa.py`)
- Agent has access to tools:
  - `search_datasets(query)` - Search datasets by name/code
  - `get_dataset_dimensions(source, code, dimension)` - Get available values
  - `query_dataset_values(source, code, geo, time_period, indicator)` - Fetch values
- Agent uses multi-step reasoning to find the right data
- Geographic codes mapping (Germany → DE, France → FR)
- Time period interpretation (this quarter → 2025-Q4)

### US-14.4: Q&A Input Interface

**As a** user
**I want to** have a clean, accessible interface for asking questions
**So that** the interaction feels natural and intuitive

**Acceptance Criteria:**

- [ ] Q&A interface is accessible from the main navigation (new "Ask" tab)
- [ ] Input field with placeholder: "Ask a question about economic data..."
- [ ] Submit button and keyboard shortcut (Enter)
- [ ] Loading state while the agent processes the question
- [ ] Response area shows:
  - The answer in clear, readable format
  - Data table if multiple values are returned
  - Source attribution with dataset link
  - Timestamp of the data
- [ ] Example questions are shown for first-time users
- [ ] Previous questions/answers are listed in a conversation-style layout
- [ ] "Clear conversation" button to start fresh

**UI Components (htmx + Alpine.js):**


### US-14.5: Q&A Follow-up Questions

**As a** user who received an answer
**I want to** ask follow-up questions in context
**So that** I can drill deeper without repeating myself

**Acceptance Criteria:**

- [ ] After receiving an answer, follow-up questions understand context
- [ ] Examples:
  - Initial: "What is GDP for Germany?"
  - Follow-up: "What about France?" → understands user wants GDP for France
  - Follow-up: "Show me the trend" → shows historical GDP data
- [ ] Context is maintained for up to 5 exchanges
- [ ] User can explicitly "start new topic" to reset context
- [ ] The agent indicates when it's using context vs. treating as new question

**Technical Notes:**

- Conversation memory stored in `ecox-agents` memory module
- Session-based conversation ID passed in requests
- Memory includes previous questions, answers, and dataset context
- Agent system prompt includes conversation history

---

### US-14.6: Handle Missing or Unavailable Data

**As a** user asking about data we don't have
**I want to** receive helpful guidance
**So that** I understand what's available and how to proceed

**Acceptance Criteria:**

- [ ] When requested data is not available, the response includes:
  - Clear statement that data wasn't found
  - Reason if known (dataset not downloaded, time period not covered, country not included)
  - Suggestions for related data that IS available
  - Option to download the relevant dataset if available in catalog
- [ ] Example responses:
  - "I couldn't find inflation data for Japan. This may be because the Eurostat HICP dataset only covers EU countries. Would you like me to search for OECD inflation data instead?"
  - "GDP data for 2025 is not yet available. The latest data is from 2024. [Show 2024 data]"

**Technical Notes:**

- Agent tool returns structured "not found" responses with reason
- Agent system prompt includes guidance for handling missing data
- Suggestions based on related datasets or time periods

## Non-Functional Requirements

### NFR-14.1: Response Time

- News summarization: < 10 seconds for standard articles (< 5000 words)
- Q&A simple queries: < 5 seconds
- Q&A complex queries (multi-dataset): < 15 seconds
- UI must show loading state for all async operations

### NFR-14.2: Cost Optimization

- Support both Claude API and Claude Agent SDK backends
- Cache summaries to avoid redundant LLM calls
- Token usage tracking via Langfuse
- Configurable model selection (e.g., use Haiku for simple tasks, Sonnet for complex)

### NFR-14.3: Error Handling

- Graceful degradation when agents service is unavailable
- Clear error messages without exposing technical details
- Retry logic for transient failures (network, rate limits)
- Fallback to "service temporarily unavailable" message

### NFR-14.4: Security

- Input validation and sanitization for user questions
- Rate limiting on agent endpoints (configurable per user/IP)
- No execution of arbitrary code from LLM responses
- Audit logging of all agent interactions

### NFR-14.5: Observability

- All agent calls traced in Langfuse
- Metrics: response time, token usage, cache hit rate
- Error rate monitoring and alerting
- User satisfaction tracking (optional thumbs up/down)

## API Endpoints (ecox-agents service)

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/agents/summarize/news/{entry_id}` | Generate/retrieve news summary |
| GET | `/api/agents/summaries/news/{entry_id}` | Get cached summary if exists |
| POST | `/api/agents/qa/ask` | Ask a question about economic data |
| GET | `/api/agents/qa/conversations/{session_id}` | Get conversation history |
| DELETE | `/api/agents/qa/conversations/{session_id}` | Clear conversation |
| GET | `/api/agents/health` | Health check for agents service |

## Data Models

### NewsSummary (new table)

| Field | Type | Description |
|-------|------|-------------|
| `id` | INT | Primary key |
| `entry_id` | INT | FK to newsentry.id, unique |
| `summary_text` | TEXT | Generated summary (< 500 words) |
| `sentiment` | VARCHAR | positive/negative/neutral |
| `key_indicators` | JSON | List of extracted indicators |
| `extracted_data` | JSON | Key data points (rates, figures) |
| `model_version` | VARCHAR | Model used (e.g., "claude-sonnet-4-5") |
| `token_usage` | INT | Tokens used for generation |
| `created_at` | TIMESTAMP | When summary was generated |
| `content_hash` | VARCHAR | Hash of source content for invalidation |

### QAConversation (in-memory or Redis)

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | UUID | Unique session identifier |
| `messages` | List | List of {role, content, timestamp} |
| `context` | JSON | Current dataset context |
| `created_at` | TIMESTAMP | Session start time |
| `expires_at` | TIMESTAMP | Session expiry (e.g., +30 minutes) |

## Out of Scope (Phase 1)

- Multi-language summaries (beyond source language)
- Complex multi-dataset comparisons with charts
- Scheduled summary generation for all new articles
- Custom summary length/format preferences
- Voice input for questions
- Export Q&A history

These may be considered for Phase 2 based on user feedback.
