# US-5.17: Independent Scrolling Layout Implementation Plan

## Overview

Fix the UX bug where the news detail panel scrolls with the page instead of staying fixed. When scrolling the feed, users lose the article they were reading because the entire page scrolls rather than just the feed panel.

## Current State Analysis

### The Problem

The CSS height chain is broken. For `overflow-y: auto` to create a scrollable container, **every ancestor must have a defined height**. Currently:

```
<body class="min-h-screen">                      ✗ min-height, not height
  <header class="sticky">                        ✓ Fixed position
  <main class="py-6">                            ✗ No height - grows to fit content
    <div x-show="activeTab === 'news'">          ✗ No height
      <div id="news-container">                  ✗ No height
        <div class="h-full flex flex-col">      ✗ h-full = 100% of nothing = auto
          <div class="flex-1 overflow-y-auto">  ✗ flex-1 but parent has no height
```

The `h-full` class on the news feed root container resolves to `height: auto` because its parent (`#news-container`) has no explicit height. This causes the entire page to scroll instead of just the feed/detail panels.

### Key Discoveries

| File | Line | Issue |
|------|------|-------|
| `index.html` | 654 | `#news-container` has no height constraint |
| `_news_feed.html` | 15 | Uses `h-full` which fails without parent height |
| `_news_feed.html` | 143 | Desktop detail panel has `overflow-hidden` but no height |

## Desired End State

- News tab uses a viewport-height container (fills available space below header/tabs)
- Left panel (feed cards) scrolls vertically within its container
- Right panel (detail panel) has its own independent vertical scroll
- Scrolling the feed does NOT affect the detail panel position
- Panel header (title, close button) remains fixed at top of panel
- Panel footer (keyboard hints) remains fixed at bottom of panel
- On mobile (<768px), continue using full-screen overlay (unchanged)

### Verification

- Scrolling the feed with a long list of entries does NOT move the detail panel content
- Scrolling a long article in the detail panel does NOT move the feed
- Keyboard navigation (↑↓) still works
- Escape key still closes the panel
- Mobile overlay behavior is unchanged

## What We're NOT Doing

- Changing the mobile full-screen overlay behavior
- Modifying the detail panel internal layout (it already uses proper flex)
- Adding CSS variables to base.html (using inline calc for simplicity)
- Changing the feed card styles or infinite scroll behavior

## Implementation Approach

Use a **viewport-height container** with `calc(100vh - Xpx)` to give the news section a fixed height. This establishes the height chain needed for `overflow-y: auto` to work.

The key insight: CSS `overflow` only scrolls when content exceeds the container's **computed height**. With `height: auto`, the container just grows, so there's nothing to scroll.

## Phase 1: Add Viewport Height to News Container

### Overview

Add explicit height constraints to establish the CSS height chain from `#news-container` down to the scrollable panels.

### Changes Required

#### 1. News Tab Container Wrapper

**File**: `ecox-client/templates/pages/index.html`
**Lines**: 649-664

Currently:
```html
<!-- Tab Content: Economical News -->
<div x-show="activeTab === 'news'" x-cloak x-transition:enter="transition ease-out duration-200"
    x-transition:enter-start="opacity-0" x-transition:enter-end="opacity-100">

    <!-- News Container - loads when tab is first shown -->
    <div id="news-container" hx-get="/api/news" hx-trigger="intersect once" hx-indicator="#global-spinner">
```

**Change**: Add height constraint using Tailwind's arbitrary value syntax. The height calculation accounts for:
- Header: ~68px (sticky, py-4 with content)
- Main padding: 24px top (py-6)
- Tab bar: ~57px (py-4 + border)
- Tab margin: 24px (mb-6)
- Total: ~173px (round to 176px for safety)

```html
<!-- Tab Content: Economical News -->
<div x-show="activeTab === 'news'" x-cloak x-transition:enter="transition ease-out duration-200"
    x-transition:enter-start="opacity-0" x-transition:enter-end="opacity-100">

    <!-- News Container - loads when tab is first shown -->
    <div id="news-container"
         class="h-[calc(100vh-11rem)]"
         hx-get="/api/news" hx-trigger="intersect once" hx-indicator="#global-spinner">
```

Note: `11rem` = 176px at default 16px font size, which accounts for header + main padding + tabs + margin.

#### 2. News Feed Root Container

**File**: `ecox-client/templates/partials/_news_feed.html`
**Line**: 15

Currently:
```html
<div x-data="newsFeed"
     data-selected-category="{{ selected_category if selected_category else '' }}"
     data-search="{{ search if search else '' }}"
     data-entry-ids="{{ entry_ids|tojson if entry_ids else '[]' }}"
     class="h-full flex flex-col">
```

**Change**: Replace `h-full` with explicit height. Since the parent now has a defined height, `h-full` would work, but we also need `overflow-hidden` to prevent the container itself from scrolling:

```html
<div x-data="newsFeed"
     data-selected-category="{{ selected_category if selected_category else '' }}"
     data-search="{{ search if search else '' }}"
     data-entry-ids="{{ entry_ids|tojson if entry_ids else '[]' }}"
     class="h-full flex flex-col overflow-hidden">
```

#### 3. Desktop Detail Panel Container

**File**: `ecox-client/templates/partials/_news_feed.html`
**Line**: 143

Currently:
```html
class="hidden lg:block w-1/2 bg-white dark:bg-slate-800 rounded-lg border border-slate-200 dark:border-slate-700 overflow-hidden"
```

**Change**: Add `h-full` to ensure the panel takes full height of its flex parent:

```html
class="hidden lg:block w-1/2 h-full bg-white dark:bg-slate-800 rounded-lg border border-slate-200 dark:border-slate-700 overflow-hidden"
```

## Testing Strategy

### Manual Testing Steps

1. **Basic independent scrolling**:
   - Load News tab with 20+ entries
   - Select an entry with long content
   - Scroll the feed list up/down
   - Verify: Detail panel stays in place

2. **Detail panel scrolling**:
   - Select an entry with very long article content
   - Scroll within the detail panel
   - Verify: Feed list stays in place

3. **Keyboard navigation**:
   - With detail panel open, press ↓ key
   - Verify: Next entry is selected and panel updates
   - Press ↑ key
   - Verify: Previous entry is selected

4. **Panel close behaviors**:
   - Press Escape → panel closes
   - Click X button → panel closes
   - Click different entry → panel updates (doesn't close)

5. **Mobile behavior** (resize browser to <768px):
   - Select an entry
   - Verify: Full-screen overlay appears
   - Scroll within overlay
   - Press back button → overlay closes

6. **Infinite scroll**:
   - Scroll to bottom of feed
   - Verify: "Loading more..." appears and new entries load
   - Verify: Works with detail panel open

### Edge Cases

- Very short feed (< viewport height): Both panels should not scroll
- Empty feed: Empty state displays correctly
- Error loading entry: Error state displays in panel

## Performance Considerations

No performance impact expected. The changes are purely CSS-based layout fixes.
